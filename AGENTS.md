
- MCP server lives in src/lib/mcp (read-only tools, OAuth via Lovable Cloud); the mcp edge function is generated by the Vite plugin — never hand-edit. Why: agents may read data but the Pi alone controls regulation.
- TV-headerns tankrutor flyttas med FLIP (translateX), medan Sonos-innehåll tonas separat och slotens layout växlar direkt. TV-ölkort ändrar höjd i ett steg när timern kommer och efter att den glidit ut. Why: Chromecast slipper layoutanimering per ruta och upprepad omritning av diagram.
- Brew-day slides outside the mobile carousel are driven outside React: one layout effect sets start transforms before paint, then moves row (or with two beer cards: beer 1 → beer 2, 1200 ms each) → card → footer (reverse on exit) via element refs, advancing on transitionend or a duration + 1500 ms watchdog; React state changes only at sequence start and end. Brew-day and cleaning slides hold the global motionLock (src/lib/motion-lock), which queues realtime callbacks, holds fetches and freezes local ticks; the pause class follows the lock via classList. Why: zero React commits and no data repaints while anything moves on Chromecast.
- TV-rengöringen ligger under sidhuvudet; rengöringskort och ölkortens gemensamma yta startar samma horisontella transform-glidning först en kort förberedelsetid efter att checklistan monterats och skuggor/filter slagits av (in och ut), med täckande enkla bakgrunder; övriga CSS-animationer pausas. Why: Chromecast hinner rita om innan glidningen så den inte hackar av samtidig ommålning.

- Kort i alla lägen byter höjd/bredd/utfyllnad i ett steg; bara transform/opacity animeras och konkurrerande animationer pausas under växlingar. Why: hela UI:t måste klara Chromecast.
- Stora levande siffervärden använder den delade RollingNumber-komponenten; sifferremsorna animerar bara transform och stoppas under rengöringsväxlingar. Why: samma lättviktiga beteende behövs i TV och andra lägen.
- RollingNumber keys digits relative to the decimal point, derives direction from absolute values, skips rolls on sign changes and caps strips at five steps with a single-step fallback; the clock keeps its forced direction. Why: negative values and changing integer widths must not produce long or mismatched rolls.
- Brew Master owns timer state and pushes timer changes to receive-timer; the TV reads the cache through realtime with a slow cache-only fallback, never pulls Brew Master on a cron schedule. Why: one writer prevents stale timer state and unnecessary cross-app requests.

- Live-punktens pulserande ring ritas som HTML ovanpå diagrammet, aldrig som SVG-animation; i TV-läge inga drop-shadow-filter, tooltips eller aktiva punkter. Why: SVG-animationer tvingar omritning av hela diagrammet på Chromecast.
- Reservpollar körs bara när realtiden inte täcker (SUBSCRIBED-grind / ingen händelse på 60 s); use-brew-data äger headerns delade källa och use-rapt-bar-data pollar bara utan ägare. Why: färre anrop och reservpollen saknade Pi-målet.
- RollingNumber ritar i vila bara siffran och vid byte en kort remsa med de passerade siffrorna. Why: mindre DOM på TV:n med samma rullning.
- Footer slots are keyed and stacked (sum reserved); content-less slots self-render at the bottom and content slots sit above them. Why: brew day timer and alarm timer can be active together.
- TimerFooter receives the active brew day from BrewingDashboard rather than opening another subscription. Why: its next-step label must use the same row as BrewDayCard.
- Sonos realtime reads the widget's current-state ref to seed first/wake playback position outside the React updater. Why: progress must not depend on updater scheduling.
- TV event effects use useTvEventAnimation with stable event identities, skip the initial value and cancel on the motion lock; bar values use full-width transform layers. Why: one-shot feedback must not compete with the existing slide sequences or animate layout.
- Header relay indicators read cooling_relay_on/heating_relay_on from the existing shared Pi live-state feed, not controller enable flags. Why: enabled regulation is not the relay's actual on/off state.
